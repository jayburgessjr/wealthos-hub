# Desk build: CONTEXT (authoritative agent packet)

Objective: internal trading desk for up to two allowlisted owners (migration 20261108; was single-user) ("Desk"), Bloomberg-style terminal UI, paper trading only in phase 0, human approves every trade. Additive only: do not modify existing WealthOS tables, policies, auth, simulations, or existing edge functions.

Read first: `docs/builds/desk/ARCHITECTURE.md` (schema DDL, triggers, ADRs, threat table). It is the design authority. Deviations already decided by the Lead:
- `desk_instruments.asset_class` also allows `'crypto'`; `Structure` also has `'crypto'` (crypto scanner + Alpaca crypto). Update the DDL checks accordingly (`desk_proposed_orders.structure`, `desk_orders.structure`, `desk_positions.structure`).
- Shared pure TS already written (do not edit): `supabase/functions/_shared/desk/{types,hash,scorecard,scanners}.ts`, `risk/{limits,options,engine}.ts`, `broker/{port,paper,alpaca,factory}.ts`. Vitest imports them via relative paths from `src/test/desk/`.

Hard rules (CLAUDE.md + global): never weaken RLS/tenant isolation; no secrets in client or repo; no `any` without reason; no em dashes in copy; sentence case headings; brand: single orange accent `hsl(20 82% 51%)` (`--accent`), dark navy/ink surfaces, no gradients, no teal. Do NOT run git commit/push. Do NOT edit files outside your assigned list. No Supabase remote operations (no db push, no deploy, no MCP apply_migration).

Frontend-facing function contracts (JSON over `supabase.functions.invoke`, owner JWT attached automatically):
- `desk-claim-owner` `{}` -> `{ ok: boolean, owner: boolean, error?: string }`
- `desk-account` `{}` -> `{ ok, mode: 'paper'|'live', broker: string, account: { equity, cash, buyingPower, asOf }, positions: { symbol, qty, avgPrice, marketValue }[], state: { halted, halted_reason, halted_at, high_water_mark, day_start_equity, last_equity }, quotes: Record<string, number>, limits: typeof RISK_LIMITS }`
- `desk-approve-order` `{ proposed_order_id, decision: 'approved'|'rejected', live_confirmation?: string }` -> `{ ok, decision, risk: RiskDecision, order?: { id, status, broker_order_id, filled_qty, avg_fill_price }, error?: string }`
- `desk-reset-kill-switch` `{ note: string }` -> `{ ok, error? }`
- `desk-run-agent` `{ agent: string, symbol?: string }` -> `{ ok, run_id, signals: number, theses: number, proposals: number }`
- `desk-scorecard` `{}` -> `{ ok, scored: number }`
Modify = owner edits qty/limit/stop of a pending proposal in the UI; UI calls `desk-approve-order` only after patching via the `desk_proposed_orders` owner UPDATE policy limited to pending rows (qty, limit_price, stop_price, target_price). Reject = `decision:'rejected'`.

Tables the UI reads with the owner session (RLS): desk_state, desk_instruments, desk_signals, desk_theses, desk_proposed_orders, desk_orders, desk_positions, desk_journal (also INSERT), desk_scorecard, desk_risk_events, desk_agent_runs. RPC: `is_desk_owner()`.
